Dynamic pages · Concept

Concept On a dynamic page the server sends a document without the data, and a script fetches the data after the page has loaded.

offers.html of the shop
The response is what requests receives: the document as the server wrote it.
The DOM is the tree the browser holds after running the scripts. On a dynamic page the two differ.

Dynamic pages · Mechanism: repeat the request of the script

Mechanism The script got its data over HTTP. The browser records that request, and Python can send the same one.

  • 1. Open the developer tools of the browser (F12) and choose the Network tab.
  • 2. Reload offers.html and filter the list to Fetch/XHR.
  • 3. Read the one request listed: its URL ends in api/offers.json and its response is JSON.
  • 4. Send that request from Python.

Dynamic pages · Mechanism: drive a browser

Mechanism continued 1 When the request of the script cannot be repeated, Selenium starts a real browser, lets the script run and reads the DOM.

from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

opts = webdriver.ChromeOptions()
opts.add_argument('--headless=new')
driver = webdriver.Chrome(options=opts)
try:
    driver.get(BASE + 'offers.html')
    CARD = (By.CSS_SELECTOR, 'article.offer')
    print(len(driver.find_elements(*CARD)), 'cards straight after get()')
    WebDriverWait(driver, 10).until(EC.presence_of_element_located(CARD))
    cards = driver.find_elements(*CARD)
    print(len(cards), 'cards after the wait')
    name = cards[0].find_element(By.CSS_SELECTOR, '.name').text
    print(cards[0].get_attribute('data-sku'), '|', name)
    auto = driver.execute_script('return navigator.webdriver')
    print('navigator.webdriver =', auto)
finally:
    driver.quit()                      # always close the browser
output, Selenium 4.44.0 with headless Chrome
0 cards straight after get() 12 cards after the wait SM1162 | Pothigai Full Cream Milk navigator.webdriver = True
0 cards straight after get(). get() returns when the document has loaded. The script adds the cards 400 ms later.
An explicit wait names the element the code needs and polls until it exists or ten seconds pass.
Dynamic pages · Cost

Cost The same 12 offers took 16 ms through the JSON address and 1.51 s through a browser, on a local copy of the shop.

time to collect the offers, local server
About 96 times slower. The browser starts a process, loads the page and its stylesheet, runs the script and waits for it.
More to maintain. The browser and its driver have to be installed and kept at matching versions on every machine that runs the scraper.
Visible to the page. Scripts on the page can ask the browser whether it is automated. In this run navigator.webdriver was True.
Order of attempts. Look for the JSON request first. Drive a browser only when that request cannot be repeated.
Politeness · Concept

Concept A scraper shares the server with the customers of the site. A rate limit is the server refusing a client that asks too fast.

the rule of shop_server.py: at most 4 requests from one client in any one second
Status 429 Too Many Requests is the refusal. Its Retry-After header says how many seconds to wait.
A local server. The published shop is on a static host that applies no limit of its own. shop_server.py, in the module2/data folder, serves the same files with the limit.

Politeness · Mechanism

Mechanism A fetch function that reads the status: wait and retry on 429 and 5xx, stop on every other error.

UA = {'User-Agent': 'da5500w-student (name@example.org)'}

def get(url, tries=5):
    for attempt in range(tries):
        r = requests.get(url, timeout=10, headers=UA)
        if r.status_code == 429 or r.status_code >= 500:
            # wait as the server says, or 1, 2, 4 ... seconds
            wait = float(r.headers.get('Retry-After', 2 ** attempt))
            page = url.split('/')[-1]
            print(f'  {r.status_code} on {page}, waiting {wait:g} s')
            time.sleep(wait)
            continue
        r.raise_for_status()           # 403 or 404: stop, do not retry
        return r
    raise RuntimeError(f'gave up on {url}')

rows = []
for k in range(1, 8):
    rows += get(BASE + f'api/products/page-{k}.json').json()['items']
print(len(rows), 'rows')
output
429 on page-5.json, waiting 1 s 168 rows
168 rows in 1.48 s. The function met one 429, waited the second the server asked for and carried on.
Better still, never meet the limit. With time.sleep(0.5) after each request the seven statuses were all 200 and the run took 3.6 s.

Politeness · Assumptions

Assumptions The retry function assumes the server announces its limit. Many servers block a fast client with no 429 and no Retry-After.

What the owner sees. Every request is one line in a log, with the User-Agent the scraper sent. This lecture wrote 42 lines.
  • Pause between requests. One request a second is a safe default for a small site.
  • Fetch each page once. Save the response to disk and parse from the saved copy.
  • Name the scraper in the User-Agent, with a contact address.
  • Stop on 403. A refusal is an answer from the owner. Switching address to continue is covered under the law section.
robots.txt · Concept

Concept robots.txt is a text file at the root of a site in which the owner states which paths automatic clients should leave alone.

robots.txt of the shop
# robots.txt of the simulated shop (DA5500W Module 2) # A real site serves this file from the root of its host. User-agent: * Disallow: /account/ Disallow: /api/ Allow: /api/products/ Disallow: /search Crawl-delay: 2 User-agent: GPTBot Disallow: / Sitemap: https://iitm-da.github.io/da5500w/module2/data/shop/sitemap.xml
linemeaning
User-agentstarts a group of rules; * is every client without a group of its own
Disallowa path prefix the group should not fetch; / means the whole site
Allowan exception inside a disallowed prefix
Crawl-delayseconds between requests; widely used, outside the standard
Sitemapwhere the owner lists the pages meant to be fetched
Standard. The convention dates from 1994 and was published as RFC 9309 in 2022. Everything the file does not disallow is allowed.

robots.txt · Drawbacks

Drawbacks The file says Allow: /api/products/ and the parser answered False. Two parsers can read one file differently.

orders = (['Disallow: /api/', 'Allow: /api/products/'],
          ['Allow: /api/products/', 'Disallow: /api/'])
for rules in orders:
    rp = robotparser.RobotFileParser()
    rp.parse(['User-agent: *'] + rules)
    print(rules[0], 'first ->', rp.can_fetch('*', '/api/products/page-1.json'))
output
Disallow: /api/ first -> False Allow: /api/products/ first -> True
parserwhen Allow and Disallow both match
urllib.robotparserthe first matching line in the file decides
RFC 9309the longest matching path decides, so /api/products/ beats /api/
Under the standard the product pages of the API are allowed, which is what the owner wrote. The standard library errs towards not fetching.
For real work use a parser that follows RFC 9309, such as protego, and test it on one Allow inside one Disallow.
robots.txt · Assumptions

Assumptions robots.txt works only if the client chooses to obey it. Nothing in HTTP enforces the file.

It is a request

A client that ignores the file still receives the pages. The file controls nothing by itself.

It is evidence

When access is disputed, the file shows what the owner asked for and whether the scraper had been told.

Rule for this course

Read the file before the first request. Honour Disallow for * and treat Crawl-delay as the minimum pause.

When the path you need is disallowed, the file has answered the question. The next step is an email to the owner asking for the data.
Law · Concept

Concept "Is scraping legal" is three separate questions, about the request, the copy and the people in the data.

the three questions, in the order they are asked
Judged separately. A project can pass Q1 with a public page and fail Q3 on its first column.
Scope. This section is an orientation for a data analyst and is no substitute for legal advice. The statements were checked in August 2026.
Law · Example: Q1, access, in four US cases

Example Four United States cases mark where access stops being authorised.

casewhat happenedwhat it settled
Van Buren v. United States
Supreme Court, 2021		A police officer used his own database access to look up a licence plate for payment.The CFAA covers entering parts of a system closed to you, whatever the purpose.
hiQ v. LinkedIn
Ninth Circuit, 2019 to 2022		hiQ scraped public profiles. It had also used fake accounts.A public page is open to all. hiQ still lost on contract: $500,000 and an injunction.
Craigslist v. 3Taps
2013		Craigslist sent a letter and blocked 3Taps, which continued through proxies.A letter and a block revoke permission.
Meta v. Bright Data
2024		Bright Data scraped public pages while logged out.The terms bind users of the service, and a logged-out visitor is outside them.
The four together. A public page, read while logged out, without going around a block and before any instruction to stop: that collection is outside all four cases.
Law · Example: Q1 in India

Example continued 1 The Information Technology Act, 2000 has a civil section and a criminal section on access to a computer system.

Section 43: civil

A person who, without permission of the owner, accesses a computer system or downloads, copies or extracts data from it is liable to pay compensation. No intent is required.

Section 66: criminal

The same acts done dishonestly or fraudulently: imprisonment up to three years, or a fine up to ₹5 lakh, or both. Without that intent the section does not apply.

Untested. No reported Indian judgment applies section 43 to the scraping of a public website. The Act does not define "without permission".
Working rule. Plan for the stricter reading: public pages, logged out, robots.txt honoured, and a stop at the first refusal.
Law · Example: Q3, personal data

Example continued 2 The Digital Personal Data Protection Act, 2023 applies as soon as one column describes an identifiable person.

termmeaning
Personal datadata about an identifiable individual: a name with a phone number
Data Fiduciarywhoever decides why and how the data is processed, which includes the person who scrapes it
Lawful basisconsent, or one of a short list of legitimate uses in section 7
"Publicly available" is narrow. Section 3(c)(ii) exempts data made public by the person it describes, or by someone the law obliges to publish it. Data that another party put online is not exempt.
DPDP Rules: what applies from when
Penalties in the Schedule reach ₹250 crore for failing to secure personal data.
Habit. Decide at parse time which fields are personal, and drop or hash them before the table is saved.
Law · Mechanism

Mechanism The three questions asked in order before the first request of a project, each with the outcomes that stop or change it.

The settled case. A logged-out collection of public pages that honours robots.txt, keeps facts and drops personal fields passes all three questions under the United States and Indian law described here.

Record · Example

Example Each fetch is saved as it arrived, with one log row that says where it came from and when.

import hashlib, datetime, pathlib
pathlib.Path('raw').mkdir(exist_ok=True)
log = []
for k in range(1, 4):
    url = BASE + f'catalogue/page-{k}.html'
    r = get(url)
    name = f'raw/page-{k}.html'
    pathlib.Path(name).write_bytes(r.content)      # the page as it arrived
    log.append({'url': url.split('shop/')[-1],
                'fetched': datetime.datetime.now().isoformat(timespec='seconds'),
                'status': r.status_code, 'bytes': len(r.content),
                'sha256': hashlib.sha256(r.content).hexdigest()[:12]})
    time.sleep(0.5)
print(pd.DataFrame(log).to_string(index=False))
Raw first. Parsing reads the saved file. A selector can then be corrected without asking the server again.
sha256 is a fingerprint of the bytes. A different value on a later fetch shows that the page changed.
With the data goes a short note: source, date, robots.txt as read, fields removed, purpose.
